## Basic Payload Detection Tests

### system() Detection

1. Direct execution:
   GET /api/cmd?action=system(whoami)
   Expected: BLOCKED

2. URL-encoded:
   GET /api/cmd?action=system%28whoami%29
   Expected: BLOCKED

3. Case variation:
   GET /api/cmd?action=System(whoami)
   Expected: BLOCKED

4. Mixed case (encoded):
   GET /api/cmd?action=SyStEm%28whoami%29
   Expected: BLOCKED

5. With arguments:
   GET /search.php?q=system(id)&type=advanced
   Expected: BLOCKED

### passthru() Detection

1. Direct execution:
   GET /api/cmd?func=passthru(ls)
   Expected: BLOCKED

2. URL-encoded:
   GET /api/cmd?func=passthru%28ls%29
   Expected: BLOCKED

3. Case variation:
   GET /api/cmd?func=Passthru(ls)
   Expected: BLOCKED

4. With pipes:
   GET /api/cmd?cmd=passthru(whoami | id)
   Expected: BLOCKED

## Test Cases Using curl

### Test 1: Basic system() Call
```bash
curl -v "http://your-domain.com/api/cmd?action=system(whoami)"
# Expected: 403 Forbidden
# CloudWatch: Check for BlockedRequests metric increase
```

### Test 2: URL-Encoded Payload
```bash
curl -v "http://your-domain.com/api/cmd?action=system%28whoami%29"
# Expected: 403 Forbidden
# Note: Even though encoded, the URL_DECODE transformation will detect it
```

### Test 3: Mixed Case
```bash
curl -v "http://your-domain.com/api/cmd?action=System(whoami)"
# Expected: 403 Forbidden
# Note: LOWERCASE transformation will normalize case
```

### Test 4: passthru() Detection
```bash
curl -v "http://your-domain.com/api/cmd?cmd=passthru(id)"
# Expected: 403 Forbidden
```

### Test 5: Legitimate Request (Should be ALLOWED)
```bash
curl -v "http://your-domain.com/api/search?q=how+to+use+system+tools"
# Expected: 200 OK
# Note: "system" as a keyword ≠ "system(" function call
```

### Test 6: Multiple Parameters
```bash
curl -v "http://your-domain.com/api/cmd?param1=test&cmd=system(whoami)&param2=value"
# Expected: 403 Forbidden
```

## Bash Script for Batch Testing

```bash
#!/bin/bash
# WAF Testing Script

DOMAIN="your-domain.com"
RULE="BlockSuspiciousRCEPatterns"
EXPECTED_BLOCK="403"

# Color output
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# Test cases
declare -a TESTS=(
    "http://$DOMAIN/api/cmd?action=system(whoami):BLOCK"
    "http://$DOMAIN/api/cmd?action=system%28whoami%29:BLOCK"
    "http://$DOMAIN/api/cmd?action=System(whoami):BLOCK"
    "http://$DOMAIN/api/cmd?func=passthru(ls):BLOCK"
    "http://$DOMAIN/api/search?q=normal+query:ALLOW"
    "http://$DOMAIN/api/products?id=123:ALLOW"
)

echo "====================================="
echo "AWS WAF Testing Suite"
echo "Domain: $DOMAIN"
echo "====================================="

PASSED=0
FAILED=0

for test in "${TESTS[@]}"; do
    URL="${test%:*}"
    EXPECTED="${test##*:}"

    echo ""
    echo -e "${YELLOW}Testing:${NC} $URL"
    echo "Expected: $EXPECTED"

    RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" "$URL")

    if [ "$EXPECTED" = "BLOCK" ] && [ "$RESPONSE" = "403" ]; then
        echo -e "${GREEN}✓ PASSED${NC} (Got 403)"
        ((PASSED++))
    elif [ "$EXPECTED" = "ALLOW" ] && [ "$RESPONSE" != "403" ]; then
        echo -e "${GREEN}✓ PASSED${NC} (Got $RESPONSE)"
        ((PASSED++))
    else
        echo -e "${RED}✗ FAILED${NC} (Got $RESPONSE)"
        ((FAILED++))
    fi
done

echo ""
echo "====================================="
echo "Results: $PASSED passed, $FAILED failed"
echo "====================================="
```

## Monitoring Test Results

```bash

  --statistics Sum
```

## Troubleshooting

### False Positives (Legitimate Traffic Blocked)

If legitimate requests are being blocked:

1. Check the blocked URI patterns in CloudWatch Logs
2. Identify legitimate uses of blocked keywords
3. Create an allowlist rule with HIGHER priority (lower number)
4. Document the exception with reason

Example: If /api/system-status legitimately has "system" in the URI:

```hcl
rule {
  name     = "AllowSystemStatusEndpoint"
  priority = 0  # Higher priority than blocking rule

  action {
    allow {}
  }

  statement {
    byte_match_statement {
      search_string       = "/api/system-status"
      position_constraint = "STARTS_WITH"
      field_to_match {
        uri_path {}
      }
    }
  }
}
```

### False Negatives (Attack Not Detected)

If an attack payload is NOT being blocked:

1. Check if the pattern matches byte-for-byte (case sensitive BEFORE transformations)
2. Verify transformations are applied correctly
3. Check if the payload is in a different field (headers vs query string)
4. Consider advanced encoding techniques

### CloudWatch Logs Not Appearing

1. Verify WAF logging is enabled
2. Check CloudWatch Log Group permissions
3. Ensure sampled_requests_enabled = true in visibility_config
4. Wait a few minutes for logs to propagate

## Performance Testing

Test WAF impact on response times:

```bash
#!/bin/bash
# Simple performance test

DOMAIN="your-domain.com"
ITERATIONS=100

echo "Running $ITERATIONS requests to measure latency..."

for i in $(seq 1 $ITERATIONS); do
    START=$(date +%s%N)
    curl -s -o /dev/null "http://$DOMAIN/api/products"
    END=$(date +%s%N)
    DURATION=$(( (END - START) / 1000000 ))
    echo "Request $i: ${DURATION}ms"
done
```

Expected: <50ms per request (WAF overhead typically <10ms)
