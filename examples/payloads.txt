SIGNATURE TEST REQUESTS - FOR AUTHORIZED TESTING ONLY
=====================================================

IMPORTANT: Only send these requests to environments you own and have authorization to test.

These requests carry the signatures the WAF rules look for. They do NOT contain a PHP2Shell
exploit and cannot trigger CVE-2026-109618 or CVE-2026-109619. They only confirm that each
rule matches.

In COUNT mode (rule_action = "COUNT") every request returns normally; confirm matches with
sampled requests. In BLOCK mode matching requests return 403 Forbidden.

===============================================================================

## Test cases

Set your target first:

    DOMAIN="https://your-domain.com"

### 1. php2shell-UserAgent-Block

    curl -s -o /dev/null -w "%{http_code}\n" -A "php2shell-test" "$DOMAIN/"
    # Expected: match (403 in BLOCK mode)

    curl -s -o /dev/null -w "%{http_code}\n" -A "PHP2Shell/1.0" "$DOMAIN/"
    # Expected: match (LOWERCASE transformation)

### 2. php2shell-Exploit-Boundary-Block

    curl -s -o /dev/null -w "%{http_code}\n" \
      -H "Content-Type: multipart/form-data; boundary=B7kQpoc618" \
      --data-binary $'--B7kQpoc618\r\nContent-Disposition: form-data; name="a"\r\n\r\n1\r\n--B7kQpoc618--\r\n' \
      "$DOMAIN/"
    # Expected: match

    curl -s -o /dev/null -w "%{http_code}\n" \
      -H "Content-Type: multipart/form-data; boundary=B7kQpoc619" \
      --data-binary $'--B7kQpoc619\r\nContent-Disposition: form-data; name="a"\r\n\r\n1\r\n--B7kQpoc619--\r\n' \
      "$DOMAIN/"
    # Expected: match

### 3. php2shell-Upload-Progress-Block

    curl -s -o /dev/null -w "%{http_code}\n" \
      -b "PHPSESSID=test" -F "PHP_SESSION_UPLOAD_PROGRESS=test" "$DOMAIN/"
    # Expected: match (POST + field + session cookie)

    curl -s -o /dev/null -w "%{http_code}\n" \
      -F "PHP_SESSION_UPLOAD_PROGRESS=test" -F "PHPSESSID=test" "$DOMAIN/"
    # Expected: match (session ID in the body)

    curl -s -o /dev/null -w "%{http_code}\n" \
      -F "PHP_SESSION_UPLOAD_PROGRESS=test" "$DOMAIN/"
    # Expected: no match from this rule (no session ID); rule 5 still matches if enabled

### 4. php2shell-Oversize-Body-Block (if enable_oversize_body_block = true)

    head -c 10000 /dev/zero | tr '\0' 'a' | \
      curl -s -o /dev/null -w "%{http_code}\n" --data-binary @- "$DOMAIN/"
    # Expected: match (body > 8192 bytes)

### 5. php2shell-Temporary-Multipart-Block (if enable_multipart_block = true)

    curl -s -o /dev/null -w "%{http_code}\n" -F "name=value" "$DOMAIN/"
    # Expected: match (any multipart request)

### 6. Legitimate requests

    curl -s -o /dev/null -w "%{http_code}\n" "$DOMAIN/?search=normal+query"
    # Expected: allowed

    curl -s -o /dev/null -w "%{http_code}\n" -d "name=value" "$DOMAIN/"
    # Expected: allowed (small urlencoded form)

===============================================================================

## Checking matches

    WAF_ARN="$(cd terraform && terraform output -raw web_acl_arn)"

    for RULE in php2shell-UserAgent-Block php2shell-Exploit-Boundary-Block \
                php2shell-Upload-Progress-Block php2shell-Oversize-Body-Block \
                php2shell-Temporary-Multipart-Block; do
      echo "== $RULE"
      aws wafv2 get-sampled-requests \
        --web-acl-arn "$WAF_ARN" \
        --rule-metric-name "$RULE" \
        --scope REGIONAL \
        --time-window StartTime=$(date -u -d '10 minutes ago' +%s),EndTime=$(date -u +%s) \
        --max-items 10 \
        --query 'SampledRequests[].[Action,Request.Method,Request.URI]' --output text
    done

Sampled requests can take a few minutes to appear.

## Troubleshooting

### Request not matched

1. Check the Web ACL is associated with the resource you are testing
2. Check the optional rule is enabled in terraform.tfvars
3. Body rules only see the first 8 KB on ALB (16 KB on CloudFront/API Gateway by default)
4. A proxy or CDN in front of the WAF may rewrite headers or bodies

### Legitimate traffic matched

1. Review the sampled requests for the rule
2. Disable enable_multipart_block or enable_oversize_body_block on apps that accept uploads
3. Or add an allow rule with a lower priority number for the specific upload path
